USD BRep Python API#

The usd_brep package exposes the SM_API and SM_API_USD layers to Python through pybind11.

Installing#

pip install usd-brep

CPython 3.12 on Windows or Linux (x86_64, aarch64). The wheel bundles the OpenUSD runtime it was built against, so no separate OpenUSD installation is needed and nothing is added to the pxr namespace. On Windows it also needs the Microsoft Visual C++ Redistributable.

The prebuilt package is an alternative. Like the wheel, it bundles its OpenUSD runtime, including OpenUSD’s pxr modules, so you supply only a CPython 3.12 interpreter. It is importable once its python and usdpy directories are on PYTHONPATH and its lib and extraLibs directories are on the platform’s library search path (LD_LIBRARY_PATH on Linux, PATH on Windows), set before Python starts.

Using the Python API#

Functions are also grouped into submodule attributes of usd_brep (primitives, curves, surfaces, booleans, sweeps, fillets, offset, io, brep_ops, stitching, usd, …). These are pybind11 submodules rather than importable Python modules, so they are reached as attributes — usd_brep.usd.export_brep(...) — and the functions they hold are the same objects documented below.

The compiled module underneath is named _omni_solid and importing it directly still works, but usd_brep is the supported name: it also registers the library search path on Windows and points OMNISOLID_PLUGIN_PATH at the packaged omniSolid schema, both of which a bare import _omni_solid leaves to the caller.

Import usd_brep before opening any stage with pxr: it registers the omniSolid schema plugin, and OpenUSD ignores schema plugins registered after it has loaded its schema types. Otherwise, set PXR_PLUGINPATH_NAME to the omniSolid resources directory.

combined body. The two input Breps are consumed and must not be reused.

  • boolean_intersection – Convenience wrapper for INTERSECTION.

  • boolean_with_options – Same with cookie-cutter, imprinting flags.

  • merge_breps – N-ary version that combines a list in one call.

  • origin – Base point (x, y, z). The helix is centered on the +Z axis through this point, running from Z = origin.z to origin.z + height and starting on the +X side.

  • height – Axial length along +Z. Must be in [1e-7, 1e18].

  • radius_start – Radius at the base (Z = origin.z). Must be in [1e-7, 1e18] (zero is rejected).

  • radius_end – Radius at the top (Z = origin.z + height). Must be in [1e-7, 1e18] (zero is rejected); a value different from radius_start produces a conical (tapered) helix.

  • turns – Number of full 360-degree revolutions over height. Fractional turns are allowed, but below ~1 turn the helix winds steeply (nearly straight): a tight tolerance may be unmeetable (raising SM_ERR_NOT_WITHIN_TOLERANCE – loosen it) and such near-straight paths may be rejected by pipe_sweep. Use turns >= 1 for a reliable sweep path. Must be in [1e-7, 124.25] (the upper bound is the fitter’s control-point limit).

  • right_handed – If True (default) the helix winds counter-clockwise about +Z; False gives a left-handed helix. Keyword-only.

  • tolerance – Guaranteed maximum 3D deviation of the returned curve from the true helix. Must be in [1e-6, 1e18]. This is a hard bound, not best-effort: the achieved deviation is verified after fitting and the call fails if it cannot be met (see Raises). Keyword-only.

Returns:

helical curve within tolerance of the analytic helix.

Return type:

BSplineCurve

Raises:

Notes

The helix is built about the world +Z axis at origin. To orient it along another axis, transform the resulting curve.
